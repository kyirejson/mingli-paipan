## 三、详细发现

### F01：晚子时跨盘口径尚未统一

**证据：E01、E02、E03。** 调用同一套实际发布的引擎和修复层，输入 `2026-10-29 23:30`：

| 模块 | 日柱 | 时柱 | 时旬空 |
|---|---|---|---|
| 公共 calendar | 丙子 | 庚子 | 辰巳 |
| 奇门默认盘 | 丙子 | 庚子 | 辰巳 |
| 六爻默认时间卦 | 丙子 | 戊子 | 午未 |
| 梅花默认时间卦 | 丙子 | 戊子 | 午未 |

原因：`divination-calendar-fix.js` 只包装 `liuyao`、`meihua`，公共 `calendar` 和奇门计算没有同步修正。奇门此次返回的 `activeGz` 为庚子。

**影响路径：**晚子时输入 → 不同盘读取不同时间规则 → 同一命例显示不同的时柱和空亡。不同流派可以采用不同换日规则，但当前没有在这些盘中清楚解释差别。不能仅凭此表断言整个奇门起局算法都错误，也不能把其他模块直接套用六爻补丁。

**建议及验收：**先制定逐盘的换日规范，再统一时间数据接口或明确显示所选口径。覆盖 22:59、23:00、23:59、00:00、00:01，分别核对日柱、时柱、旬空和奇门起局所用干支；八字与紫微也应纳入真实页面验收。

### F02：紫微助手在手机发布包中没有可用的服务链路

**证据：E01、E07。** `fivearts-ui.js:892` 使用相对地址 `/api/ziwei-assistant`。手机内嵌网页没有配置外部服务地址；`scripts/dev-server.py:73` 只监听开发电脑的 `127.0.0.1:9988`，允许的 Origin 也限于本机 HTTP 地址。GitHub 备份没有收录这个本地服务。现有 Python 测试使用模拟响应，并非真实 DeepSeek 连接验证。

**影响路径：**手机打开紫微助手 → 发送问题 → 请求无法到达当前开发电脑的代理 → 无法得到正常回答。单纯充值或更换 API key 无法补齐发布包的远程服务链路。历史 401 也不能仅凭“账户没钱”就判定根因；本次没有额外发起真实模型请求。

**建议及验收：**部署具有明确配置、凭据保护和服务状态提示的手机可达接口，验证真实回答；在完成前，页面应明确说明该功能尚不可用。需从安装后的 APK 验证超时、网络中断、凭据失效、服务错误及重复提交，而不只测试本机代理。

### F03：旧用户迁移没有闭环，不能视作普通版本更新

**证据：E01、E05、E06、README。** v1.0.8 更换了签名；发布为预发布，稳定最新版仍为 v1.0.7，且本次附件没有 `update.json`。这避免旧版误下载为覆盖更新，但也说明此前设想的“GitHub 发布后手机自动接收并升级”在这次版本上没有完成。

命例、笔记草稿、五术参数和题库进度分别存放于多个本地存储键。`android:allowBackup="true"` 不能证明用户卸载后必能恢复这些记录。本次没有找到经过实际验收的完整导出、校验、导入和新签名迁移流程；不能将“提醒用户备份”当作迁移已经可用。

**影响路径：**用户需要使用新版 → 旧签名无法直接覆盖 → 卸载旧版 → 本地命例与笔记存在丢失风险。Android 的更新签名要求见[官方说明](https://developer.android.com/google/play/app-updates)；本项目未恢复旧私钥，也未建立能解决此次变化的有效签名轮换链。

**建议及验收：**在引导已有记录的用户重装之前，提供完整迁移工具，覆盖命例、分组、正式笔记、草稿、五盘设置和题库进度。至少完成一次真实“旧版导出 → 新版导入 → 逐项数量及内容比对”。新签名下后续版本也要完成一次保留数据的覆盖升级实测。

### F04：缺少完整工程和可重复构建入口

**证据：E01、README、GitHub 备份目录。** 当前 APP 开发根目录没有 `.git`、自身的 `package.json`、安卓工程或 `gradlew`；`references/ziwei-doushu` 的工程文件属于上游参考项目，不能替代本 APP 的工程。GitHub `recovered-web` 只包含资源、部分测试和报告。v1.0.8 的安卓外壳来自 v1.0.7 APK，构建依赖 `D:\zaohua-release-work` 中的本机工具和解包目录。

**影响路径：**换电脑或丢失临时工作目录 → 克隆 GitHub → 缺少安卓构建及签名配置入口 → 无法独立复现发布。当前可以继续改网页和重打包，并不等于已恢复可长期维护的源工程。

**建议及验收：**恢复或重建完整安卓外壳、版本配置、依赖清单、构建脚本和必要的来源说明；把正式开发目录纳入版本管理。验收条件是在干净的 D 盘工作目录从仓库获得全部非秘密输入，使用独立保管的签名完成构建、验签和安装，不依赖旧电脑的私有绝对路径。固定构建工具和基础 APK 摘要。

### F05：名人资料中含明显不是真实生日的日期

**证据：E02、E03；`wzbz-native-bridge.js:847,1005`。** 内置 `MINGREN_CSV` 共 58 条，其中 10 条古代人物记录使用了 2026 年以后的日期：例如崇祯 `2091-02-09`、武则天 `2064-03-01`、朱元璋 `2048-11-03`。还有古代人物使用近现代年份。该表被本地接口直接返回。

这些日期可能意在匹配四柱，但没有可靠依据可将其当作历史出生资料。本次没有逐人考证真实生日，也没有在界面上重新操作名人入口。

**影响路径：**替代日期被当成实际出生时间 → 计算年龄、大限流年、紫微或时间卦 → 即使四柱巧合相同，也不能保证其他盘和历史运限正确。

**建议及验收：**把“有来源的真实生日”“古籍仅记四柱”“为展示而生成的替代日期”明确区分。仅四柱资料不得默认转换成其他体系的真实出生盘；资料不明的时辰不能擅自补成已知时辰。给每条可信名人记录保留来源与历法说明。

### F06：保存失败的提示与实际结果不一致

**证据：E02、E03；`fivearts-ui.js:132–151,397–404`。** `applyMethod()` 调用 `saveSession(ui.scope)` 后不检查布尔返回值，继续清除错误、关闭弹窗并提示成功。对真实函数隔离注入 `saveSession() => false`，结果仍为：

```json
{"saveSessionReturned":false,"modalClosed":true,"notices":["已应用六爻起局设置"]}
```

**影响路径：**存储满或笔记迁移异常 → 持久化失败 → 当前内存中看似生效 → 页面提示成功 → 重启后设置可能回退。

**建议及验收：**区分“当前生效”和“已保存”；保存失败保留编辑内容并显示原因。通过配额异常、损坏 JSON、迁移失败测试，确保不能错误宣称保存成功。需同时检查紫微模式及其他调用 `saveSession()` 的入口。

### F07：测试数量不能代表全项目的准确性和性能

**证据：E04、E01；`tests/divination-ui-interaction.mjs:1,8`。** 本次 22 项排盘测试通过，覆盖了六爻 4,096 组动爻状态、梅花 384 组本卦动爻等，确实提供了有用保障。两个代理测试验证了模拟请求，不验证真实模型。现有页面脚本依赖项目外的 CDP 工具及历史 `before-state.json`，GitHub 备份也没有收录它们。

尚无本次验收证据证明：八字、紫微三盘、奇门多种起局均已系统外部对盘；所有页面在不同尺寸、字体缩放、暗色模式下正常；切盘达到 120 帧；正式包在真实手机上完成升级和数据保留。

**建议及验收：**将断言所用的独立基准和运行环境写清，补齐可移植的页面测试。性能应提供设备刷新率、帧时间分布、掉帧及冷/热切换测量。设置高刷新率目标或看到动画流畅，均不能作为实际达到 120 帧的证据。

### F08：旧接口的第三方网络回退尚未封闭核验

**证据：E06。** `wzbz-native-bridge.js` 对已覆盖接口进行本地处理，末尾仍保留 `return origDispatch(cfg)`。打包脚本中存在原服务域名，如 `bzapi3.iwzbz.com`、`wzzwclient.iwzwh.com`。域名字符串存在不证明本次实际发生了联网，也不能据此宣称数据已经泄露。

**风险路径：**未覆盖的旧功能或入口 → 回退原请求 → 可能依赖非本项目控制的第三方服务。受影响功能、参数及失败时行为需逐项抓包确认。

**建议及验收：**建立明确的网络请求清单和允许列表；从真实安装包离线操作核心流程，再记录联网时的请求目标及数据字段。无意继续使用的旧接口应给出明确不可用结果，不做隐式回退。

### F09：真太阳时的展示与紫微输入来源需要重点复核

**证据：E02、E03；`fivearts-ui.js:701,934–945,960–970`。** 紫微中心区分别显示 `info.sunTime` 和 `info.solarTime`，但会话基准时间取 `info.solarTime`，`result('ziwei')` 调用 `E.ziwei(s.baseTime, ...)`。隔离原函数，给出钟表时间 `2000-01-01 00:30`、真太阳时 `1999-12-31 23:00` 时，传入引擎的仍是前者。

**当前判定：高优先级待端到端确认。** 这是代码时间来源的确切观察；尚未在真实地点与真太阳时开关流程中确认全部字段传递，因此不在本报告中宣称已复现用户侧的错误紫微命盘。

**建议及验收：**明确每个体系是否使用真太阳时，并让展示、引擎输入和缓存键保持一致。使用跨时辰和跨日期的地点样本，记录开关前后的时间、命宫身宫及四柱，避免页面显示校正时间而引擎仍用钟表时间。

### F10：笔记草稿只完整保护正文，结构化字段需要补验

**证据：E06；`paper-forest-details.js:133–137,168–178`。** 正文输入调用 `changeNote()`，写入 `wzbz_note_drafts_v1`；结构化文本字段输入只更新 `item.data` 和页面状态，未走同一草稿写入逻辑。

**风险路径：**编辑反馈或判断标签后没有显式保存 → 退出、闪退或进程回收 → 这些编辑可能无法像正文一样恢复。本次没有做真实进程终止实验，因此不将全部字段的丢失行为写作已完成动态复现。

**建议及验收：**统一正文、标签与反馈的草稿格式，或明确告知哪些内容必须手动保存。分别编辑三类内容后强制终止进程、重新打开，验证恢复与显式保存，并检查已有笔记迁移是否幂等。

## 四、应保留的现有成果与边界

- 六爻艮卦纳甲和混合类型动爻去重修复已有回归保障；本次未发现这些补丁回退。
- 梅花本互变综错与体用的穷举测试通过；这不等于每条解卦断语或各流派取法均已验证。
- v1.0.8 的本地文件与 GitHub 发布附件摘要一致，预发布状态有助于阻止旧用户误当普通升级。
- 原账号和会员仍有固定本地占位数据。此前用户允许保留部分展示，这不直接作为新增鉴权漏洞；但它不是真实登录、云同步或会员后端，不能对外宣传成已具备这些服务。
- 新签名及密码同在本地 `private-signing/`，本次未看到独立恢复演练记录。应做安全的异地备份；不要将它们放入 GitHub。`.gitignore` 已排除该目录。

## 五、整改顺序与验收标准

1. **先处理数据和时间正确性：**完成旧版导出恢复验证，明确五盘换日及真太阳时规则，修正保存失败的误提示。
2. **恢复持续开发能力：**整理完整工程、可重复构建脚本、配置和可移植测试，保留新签名的独立备份。
3. **解决可见但不可用的功能：**完成手机端紫微助手真实链路；清理或正确标注名人替代日期。
4. **进行正式包验收：**真实手机、离线、低存储、进程回收、升级保留数据、多尺寸和字体缩放；记录每个问题的复现和关闭证据。
5. **最后验收高刷新率目标：**先取得切盘基线，再依据帧时间数据优化，不能以调整一个刷新率参数作为通过标准。

发布门槛应至少包括：P1 问题解决或明确限制影响范围；从仓库可复现构建；命例和笔记可导出恢复；安装后的真实手机功能与更新验收通过。当前的 22 项通过测试不足以单独满足该门槛。
