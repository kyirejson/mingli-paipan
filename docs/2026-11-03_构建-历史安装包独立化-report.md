删除电脑或 GitHub 的历史 APK 本身不会执行手机上的清除数据。此前用户旧盘丢失的唯一原因尚未确定，不能把构建输入依赖当作该问题的已证实原因。沿用 v1.0.15 的稳定存储键、独立保护副本和升级前读回检查。

## 构建与清理控制

独立原生归档为 3,102,867 字节，SHA-256 `fdd817152c70eff84bbed6c1d8447cfae5a09a1f44fdc771c5535f4a5d4b760f`。这是工程依赖，不是历史安装包。原始 Gradle/Java 工程仍未恢复，原生框架部分仍使用已恢复的二进制。

`publish-release.py --publish --prune-old-apks` 先核验新版完整 APK、签名、版本和公开清单，设置正式 latest 后再调用清理。清理器默认只读，显式执行时逐项核对 latest；最新包缺失、摘要不符或 latest 改变即停止。它只删除旧安装附件，保留当前版、未来版、草稿、历史源码标签、签名、原生输入、构建工具、测试数据和应用数据。旧版对应清单和摘要随旧 APK 一并清理，避免作为可用安装附件继续展示。

最新构建使用 `D:/zaohua-independent-build`，日常构建及旧产物清理位于 D 盘。操作说明见 [独立构建与清理](build-and-retention.md)。清理后的实际计数及最终核验见本目录 `independent-build-2026-11-03/cleanup-verification.json`。

实际已删除 GitHub 10 个旧版 APK 及其对应清单/摘要，共 21 个附件、1,082,602,445 字节。当前仅 v1.0.16 保留安装附件。已删除本机 80 个旧安装产物，释放 2,314,245,141 字节，约 2.31 GB；旧 `base.apk` 也已移除。独立原生输入、签名、构建工具、源码及历史标签保留。一次 GitHub TLS 中断后按剩余附件续跑，最终核对旧安装附件为零。

清理后再次检查模拟器，原测试命盘、笔记、草稿及原生副本仍一致，见 [清理后数据检查](independent-build-2026-11-03/android-after-cleanup.txt)。APP 已实际读取正式 v1.0.16 更新信息；这不代替用户手机的联网与安装验收。

## 验证与限制

90 项 Node 回归、13 项发布协议、9 项构建清理测试通过。测试包含新草稿附件列表刷新、篡改原生输入拒绝构建、旧网页/越界路径拒绝、最新包缺失停止清理、latest 改变中止、保留当前/未来版本和构建工具。

模拟器使用人工测试记录，上述结果不表示已经恢复用户手机上的旧盘。卸载、清除应用数据或丢失签名不属于删除安装产物；这些操作仍不可当作常规更新方式。首次从 v1.0.14 及更早版本升级前，请导出当前资料，再覆盖安装。
