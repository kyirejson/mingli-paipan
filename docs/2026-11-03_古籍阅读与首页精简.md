# 古籍阅读与首页精简

日期：2026-11-03。用户要求移除重复的快捷日期时间输入和首页小字，并解决排盘后《三命通会》《八字提要》无法阅读。用户指定自行查找网上资料。

## 已确认的问题

| 证据 | 问题 | 处理 |
| --- | --- | --- |
| `calendar-input.js` 在公历滚轮之前额外渲染 `datetime-local`，标题为“快捷输入公历日期时间” | 同一时间有两套输入控件 | 删除额外控件及其专属 CSS，现有界面验证无 date/time 原生快捷输入 |
| 首页渲染宣传语和联网、备份说明段落 | 非输入内容占据页面空间 | 删除对应渲染与失效样式，保留出生时间和正常操作按钮 |
| 对旧 `getnewguji3.php` 的真实请求返回 HTTP 200，页面却为 `vip=0` 试读结构 | 请求成功并不代表获得完整正文；会员遮罩不是简单排版错误 | 两本书改用独立公开原文页面，不修改旧源权限、不移除旧源访问标记 |
| 最初模拟器测试命盘打开失败，控制台是 `JSON.parse("original-feedback")` 异常 | 结构化笔记格式异常使整个盘初始化失败，用户看到的却是网络提示 | 新增无存储写入的笔记显示转换函数；两份排盘组件共用，保留原始记录 |

`original-feedback` 是之前覆盖保留测试使用的人工样本，不是从用户手机读取的数据。该样本暴露了真实的读取容错缺陷；不能据此断言此前用户手机丢盘的唯一原因。

## 阅读来源和对应关系

正文来自 [古籍典藏《三命通会》目录](https://luckclub.cn/bazi/005/) 和 [《八字提要》目录](https://luckclub.cn/bazi/015/)。网站可直接访问的原文按需读取；应用不附带其整本正文、现代白话译文或解析，也不访问旧站受限正文。

- 《三命通会》120 个日干时辰章节与公开目录逐条核对，再按日柱取独立分项；例如 [六壬日辛丑时断](https://luckclub.cn/bazi/005/281/) 对应壬申日辛丑时。原文没有严格的独立分项标签时，显示真实章节全段，并标明“日干时辰总论”。
- 日干页取 [论天干阴阳生死](https://luckclub.cn/bazi/005/014/) 的对应段落，处理丁火与丙火合在同一段的版式。月支页展示 [论十二月支得日干吉凶](https://luckclub.cn/bazi/005/063/) 中当月的各日干原论，避免把一个段落内的不同日干漏掉。五行页显示相应五行原典相关章节。
- 《八字提要》公开版为 120 个“月支 × 日干”章节，每章含时辰分项。不能把旧接口 1,440 条的条目序号当作网页章号。应用先定位章节，再严格查找时辰原文；例如 [丑月壬日章节](https://luckclub.cn/bazi/015/119/) 中的辛丑时分项。

当前仅更换上述两本书的来源，其余九本仍使用原有服务。新来源也可能发生网络中断或内容调整；标题、条目缺失时展示失败并允许重试，不静默显示其他书或伪造正文。

## 技术边界

只请求固定 HTTPS 主机下的两类公开章节路径，使用既有 Capacitor HTTP 能力，不新增远程代理。请求路径不携带姓名、GUID、出生地点或完整出生时间。校验响应状态、最终 URL、正文容器和章节标题，拒绝异常响应。

解析采用惰性的 DOMParser，仅提取原文段落，内容全部转义后使用本地阅读模板展示。网站脚本、导航、白话和广告不进入正文 iframe。模板限制外部资源和脚本，仅添加自身尺寸上报。缓存只在内存中保留最近 12 页，不写入命盘、笔记或安装包。继续保留切换取消、超时和旧请求不能覆盖新请求的保护。

笔记容错只处理显示副本，结构化字段损坏时回退显示默认结构；不会写回或删除原始笔记。打开损坏样本后，再次比较三组原始存储值及原生副本。
