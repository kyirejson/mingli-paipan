# 全部八字古籍注解修复与验收

本文件记录发布前的本地验收状态；正式发布信息以仓库 Releases 为准。
日期：2026-11-04。版本：v1.0.24，versionCode 25。范围是当前八字古籍入口的全部11本，包含原文、原有评注及可获取的白话译注，不只修用户举例的几本。

## 一、问题原因与现有客户端逻辑

现有客户端资产中可见的阅读链路是：四柱及所选格局 → 各书篇目匹配 → 书号、分栏、条目索引 → 请求正文页。`getGuji…_branch`生成篇目，`getIndex…`定位旧服务页码；这条链路表现为确定性目录检索，不能据此推断问真其他服务端功能是否使用模型。

本轮确认的原因有：

1. 此前只有《三命通会》《八字提要》配置独立公开来源，其余书仍依赖旧服务。历史真实探测已经记录过HTTP 200返回试读/访问提示页；客户端收到页面，不等于取得完整注解。
2. 旧公开阅读器只提取`article-content`原文区，没有读取单列的白话译文区，因而有些章节能看到古文，却看不到解说。
3. 不同底本的章节结构和页码不同，不能将旧服务的条目编号直接用于新站。例如《穷通宝鉴》有月份合章；《天元巫咸》按十干的论篇、时引、杂断、诗诀编排，不能继续把新底本挂在旧六十日柱、时柱标题下。
4. 原文带局部加粗时，旧提取器会把整段正文当标题。现改为仅独立标题和整段为标题标识时使用标题样式。
5. 公开录文本身也可能有错。《李虚中命书》一个底本出现重复且内容冲突的辛酉条。现改用有逐段对译的来源，严格定位原段；辛酉明确使用“包秀结英”段，并展示该底本存在重出的说明，不让先后顺序决定读到哪段。

本轮处理的是这条阅读、匹配、注解显示链路。没有取得问真服务端的私有评注库，不能把独立底本和站内译注说成与问真自有评注逐字相同。

## 二、11本书的实际处理

| 古籍 | 阅读与匹配范围 | 注解呈现 |
|---|---|---|
| 穷通宝鉴 | 日干与月令；真实月份合章 | 原文、本章白话 |
| 滴天髓 | 实际日干体象、官杀/伤官及体用、月令等篇目 | 原文及原注、相应白话；无法分干对齐的只作整章阅读 |
| 三命通会 | 日时、日干、月干和五行相关章节 | 对应条目译文与整章译文分开，不把相邻日柱解说套入本条 |
| 八字提要 | 月支、日干、时柱 | 原文与对应时辰白话；未知时辰可读月日各时辰原章，不假设子时 |
| 子平真诠 | 已选格局及取运篇；无格局时提供用神原理等真实篇目 | 沈氏原文、徐注等分层，另列站内白话 |
| 渊海子平 | 格局、十干体象、月令及建候诗诀 | 原文、眉批等原注、对应或整章白话 |
| 天元巫咸 | 十干论篇、时引、主用杂断、主用诗；保留戊土分开的续篇 | 完整呈现底本随文旧注；没有冒称提供独立现代译文 |
| 神峰通考 | 金不换骨髓歌断、十干体象 | 原文与站内白话；完整章节明确按章呈现 |
| 千里命稿 | 格局、六神、比劫禄刃、运限等对应原章 | 原文与本章白话，不虚构新底本没有的独立小节 |
| 五行精纪 | 年月日时、干神、节气、六十甲子等原章 | 原文与本章白话；撤回旧服务疑误日时页的请求路径 |
| 李虚中命书 | 按本盘年、日干支查古法纳音原段 | 原段和该段白话成对读取；一段包含相邻干支时保留整段并标明 |

《天元巫咸》书名对应用户所说的天元、巫咸内容，当前入口是一部书。原典、原注、现代译文不是同一种文字，页面据实区分。

章节按需在线读取，保留来源标注；没有把整批现代译文打进安装包。阅读需要来源网站可用，不代表已经建成全书离线库。书目元数据共750项，只用于正确定位来源，不等于750章逐字完成校勘，也不代表APP展示了一个新的独立书库。

## 三、显示与可靠性修复

- 解说在原文前方独立展开，原典及原注另列；整章白话若含其他条目，使用明确标题，默认与精确条目解说分开。
- 月日时、日柱、日干等分段只有找到明确边界才局部提取，避免邻项串注。不存在明确对应译文时，不伪装为本盘精确解说。
- 正文17px、舒展行距、纸色与青绿；原注用独立边线区分。320/430宽度和深浅色检查无横向溢出。
- 正文以纯文本重新排版，不执行外站脚本或复制其导航；保留出处入口。现有书籍选择、章节切换和格局设置入口继续使用。
- 撤回旧`getnewguji3.php`取文请求及权限页回退路径。源地址按固定来源白名单校验，标题不符、缺段或冲突明确失败。
- 保留超时、取消、迟响应保护和12页缓存上限；文档只解析一次。外站请求不附带姓名、生日、GUID、会员字段或登录凭证。
