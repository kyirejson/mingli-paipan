# 造化元钥：第一批性能优化实施结果

日期：2026-10-29。优化基线：本地 Git 提交 `a419219`。本次实现已批准方案的第一批：紫微反向查词索引、运限列表轻量计算与分层缓存、相邻盘面空闲预热。

## 实际改动

1. **紫微查词建立索引。** 原先每次转换星曜、宫名等文字都扫描全部语言资源。现在首次使用时建立索引，后续直接查找；保留别名优先、类型过滤和首次匹配顺序。
2. **运限列表与盘面计算分开。** 年、日、时列表的干支，复用引擎内部同一套轻量历法函数，不为每个列表项目完整重排星曜。当前选中的实际运限仍用完整计算。首次读取某年流月列表时，底层 `monthlyList()` 仍会进行完整运限计算，随后复用该年度结果。
3. **缓存按用途限制容量。** 运限显示数据移至按命盘隔离的 `WeakMap`；年度流月最多 4 组、流年区间 4 组、流日月份 6 组、流时日期 16 组，采用 LRU 淘汰。大限列表每盘生成一次。不再在响应式命盘对象上持续增加 `_cachedFlowRows`。
4. **缩小预热范围。** 默认盘就绪后延迟 600ms，仅准备排序中的相邻一盘，不再自动连续挂载五盘。拖动、动画或空闲预算不足时推迟；销毁页面时清除定时器和 idle 回调。切盘后的动画结束会重新安排相邻盘预热。

相关实现：`dist/static/js/fivearts-engine.js`、`dist/static/js/ziwei-flow-data.js`、`dist/static/js/fivearts-ui.js`、`dist/index.html`。

## 同条件前后测量

使用基线提交导出的独立静态目录与当前开发目录比较。两侧各重载测量 2 次；每次连续切换 6 个流日，共 12 个流日样本。合成出生信息固定为 `2026-10-29 12:00`，测试日期固定为 `2026-11-01` 至 `2026-11-06`。

环境：Chrome 140.0.7339.210、桌面无头浏览器、CPU 4 倍降速、430×932、禁用浏览器缓存、本地 HTTP 预览。基础八字网络请求仍使用现有路径，因此“结果宿主就绪”包含网络、计算、渲染和预热阻塞的综合时间，不能解释成纯算法耗时或第一帧显示时间。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 流日更新耗时中位数，12 次 | 5,150.7ms | 194.0ms |
| 流日更新范围 | 4,684～11,527ms | 131～244ms |
| 点击排盘至结果宿主就绪，两轮 | 16,731 / 15,485ms | 2,234 / 1,975ms |
| 初次结果观察点 DOM 元素数 | 2,122 / 2,122 | 1,328 / 1,328 |
| 初次结果观察点前最长主线程长任务 | 13,980 / 13,258ms | 1,668 / 759ms |

这一组实验中，流日更新中位耗时降低约 **96.2%**，默认进入结果页时的 DOM 元素减少约 **37.4%**。这些是有限次数实验室样本，不是安卓真机统计，也不是所有命例的性能承诺。前一份方案的测量使用另一组合成输入，因此不能将那份报告的绝对耗时与本表直接混比。

另对同年三个新日期 `2026-11-07/08/09` 插桩计数：每次变化只调用 **1 次完整 `chart.horoscope()`**，满足原方案 1～2 次的预算。之前定位阶段曾测到每次 24～54 次完整调用。

## 切盘与帧率的实际限制

本轮 10 次切盘包含首次访问未预热的盘面。优化前两轮 rAF 间隔 P95 为 133.4 / 66.6ms，优化后为 116.6 / 150.0ms；优化后最大间隔仍达 250 / 266.7ms。**这组数据没有证明切盘帧时间获得稳定改善。** 首次挂载、布局和渲染仍需要后续定位，不能只用流日计算提速来宣称切盘卡顿已经全部消除。

当前没有连接的安卓模拟器或真机。本轮没有安卓安装验收、WebView 帧时间或真实 120Hz 设备数据，不能宣称达到 120fps。`requestIdleCallback` 也没有把预热计算移出主线程；本轮只限制范围和调度时机。

没有据一次堆内存读数宣称修复内存泄漏或降低内存：GC 和首次加载的盘面数量会影响读数。已落实的是缓存容量限制，长期保留内存仍需快照验证。
